# Domain docs

Layout: single-context. CONTEXT.md at the repository root is the shared vocabulary and
ownership map; package-specific architecture decisions live under the owning package's
docs/adr/. Read the relevant decision before changing that boundary.

Task acceptance criteria belong to the owner's request or linked GitHub issue, not the
glossary. Update resolved terminology in CONTEXT.md, record a lasting responsibility or
lifecycle decision as an ADR, and surface contradictory decisions before replacing them.
Keep historical migration evidence in docs/archive; it is loaded for the affected history,
not as a prerequisite for every task. See issue-tracker.md for coordination conventions.
